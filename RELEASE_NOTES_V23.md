# Релиз v23 — серверная авторизация и целостность операций

Дата: 11.11.2026

## Что исправлено

1. **Серверная сессия бариста стала обязательной.** `submit_checklist`, `submit_cash`, `batch_submit_cash`, `upload_photo`, `ack_announcement` и `report_standalone_incident` больше не принимают имя сотрудника как доказательство личности. Требуется действующая серверная сессия роли `staff`; имя в записи берётся из сессии.
2. **Вход бариста действительно получает серверный токен.** PIN проверяется сервером, запрос входа ожидается до подтверждения профиля. Раньше UI лишь проверял PIN локально и мог продолжить работу с `st_local_*`, который сервер не мог подтвердить.
3. **Вход владельца также выполняется через сервер.** Локальная проверка используется только как офлайн-резерв при сетевой ошибке. Ошибка сервера больше не маскируется успешным локальным входом.
4. **Убрано автоматическое создание локальной admin-сессии при открытии `owner.html`.**
5. **GET-запросы владельца используют `sessionToken`, а не PIN в URL.** Это применено к панели, отчётам и управлению.
6. **После `FACTORY_PINS_DISABLED=1` заводские PIN больше не используются как fallback.** Если хеш администратора отсутствует, сервер возвращает `SECURITY_NOT_CONFIGURED`. Для неизвестных сотрудников больше нет общего fallback PIN `1111`.
7. **Валидация даты проверяет календарную корректность**, поэтому `2026-02-31` отклоняется, а не нормализуется браузерным Date.
8. **Пакетная отправка кассы** ограничена 1–31 днями, проверяет каждую дату и сумму и привязывает имя сотрудника к проверенной сессии.
9. **Service Worker обновлён до кэша v23**, чтобы клиенты получили новые JS/HTML.

## Важные ограничения

Локальные тесты используют mock Google Apps Script и не подтверждают права доступа реального Drive, таблицы или опубликованного Web App. После развёртывания обязательно пройти чек-лист v23 на копии таблицы. Офлайн-сессия `st_local_*` не даёт серверных прав; после восстановления сети сотруднику нужно войти повторно, чтобы получить серверный токен.
