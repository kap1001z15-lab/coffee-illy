# STATE MACHINES — Машины состояний ключевых процессов Coffee Illy (Этап 2)
Актуальная версия: v71

## 1. Жизненный цикл операции синхронизации (`Operation Lifecycle`)
`[Created Locally]` → `[Validated]` → `[Queued in FIFO Outbox (operationId)]` → `[Sent via coffeeFetch]` → `[Server Auth & Validation]` → `[Idempotency Check (API_OPERATIONS)]` → `[Committed to Google Sheets]` → `[DATA_REV Incremented]` → `[Client Confirmed & Outbox Cleared]` → `[Broadcast to Other Devices]`.
- При обрыве связи операция остаётся в `[Queued in FIFO Outbox]` со статусом `🟡 На устройстве · ожидает отправки`.
- При ошибке валидации (`VALIDATION_FAILED`) операция помечается `failed`, не блокируя последующие элементы очереди.

## 2. Жизненный цикл этапа смены / чек-листа (`Checklist Window State`)
- `waiting_open` («До открытия окна») → `open` («Доступ открыт / В работе») → `completed` («Выполнено в срок») ИЛИ `overdue_closed` («Просрочено · Доступ закрыт, создан инцидент просрочки») → `unlocked_by_admin` («Продлено администратором с записью причины в аудит») → `completed_late` («Выполнено с опозданием»).

## 3. Жизненный цикл инцидента / поломки (`5-Status Incident State Machine`)
1. `Новая проблема` (создана бариста с фото/видео или автоматически при просрочке; генерируется уведомление `P0`/`P1`).
2. `Принята в работу` (назначен ответственный исполнитель, фиксируется время реакции).
3. `Ожидает решения` (ожидание запчастей, мастера или поставки).
4. `Решена` (работы выполнены исполнителем, ожидает подтверждения управляющего; активные напоминания прекращаются).
5. `Закрыта` (проверена и подтверждена руководителем; остаётся в архиве и истории без удаления).

## 4. Жизненный цикл задачи в Канбан-доске (`5-Column Task State Machine`)
`1. Новые` → `2. Назначены` → `3. В работе` → `4. На проверке` (для задач с обязательным фотоконтролем) → `5. Выполнены`.
